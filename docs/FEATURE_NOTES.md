# 待办与需求草案

## 一、收藏与回顾（用户 2026-09-20 提出）

### 现状与问题

- 「远望书友 → 查看最近回复」读的是 `main.lua:238` 的 `self.last_reply`，
  **纯内存字段**——关闭书籍（Reader 实例销毁）或重启 KOReader 就没了，所以显示"记录为空"。
- 真正的问答历史**一直都在**：`data/history/<书籍指纹>.json`（`ywbf/store.lua`）。
  菜单没接上去，而且条目里没有：收藏标记、书名、章节名、时间戳展示、检索入口。

### 目标

1. 觉得某段问答有价值 → 可以**收藏**；
2. 有一个地方**回顾**收藏，按书分开；
3. **支持检索**。

### 条目应展示的信息

书名 · 章节名 · 引用的段落文本 · 用户的提问 · 小望的回复 · 时间

### 数据模型（`ywbf/store.lua` 的 entry 扩展，向后兼容老数据）

```lua
{ role, content, kind, selection, ts,        -- 现有
  favorite    = true,      -- 收藏标记（新增）
  book_title  = "…",       -- 书名（新增；老数据没有则回退显示"未知书"）
  book_fp     = "…",       -- 书籍指纹（新增，便于跨书聚合）
  chapter_title = "…",     -- 章节名（新增，从 progress 取）
  chapter_index = 3, page = 42,
  question    = "…"        -- 用户提问（新增；目前 assistant/user 是两条独立 entry）
}
```

关键决定：
- **不另建收藏文件**，直接在 history 的 entry 上加 `favorite` 字段——两份数据迟早不同步。
- **问答要成对**：现在是两条独立 entry（user / assistant），收藏时要把它们绑成一对
  （建议新增 turn_id，或收藏时以 assistant 条目为主、回查同 selection 的最近一条 user）。
- **书名**：append 时写入 entry；另建 `data/books.json`（fp → 书名/最后打开时间）便于跨书列表。
- **章节名**：`Spoiler` 已经能算出当前章节（`Spoiler.currentConfig/fetchProgress`），
  append 时顺手写进去即可，不额外花钱。
- **AI 出题（kind = ideas）不进历史**（已有约定），因此也不参与收藏。

### UI

- 结果卡片（`Asker:showResult`、深聊每轮）加「收藏 / 取消收藏」按钮；
- 菜单新增「我的收藏」→ 子项：
  - 本书收藏（当前书）
  - 全部收藏（按书名分组，组内按时间倒序）
  - 搜索（跨书全文，命中提问 / 引用段落 / 回复）
- 点开一条 → TextViewer 展示完整问答，底部「取消收藏 / 删除」；
- 列表项摘要：`书名 · 第 N 章 章节名 — 提问前 20 字`。

### 工作量

中等，约 2–3 个工作日（store 字段扩展 + 收藏按钮 + 两个列表页 + 检索）。

### 已确认要做的三项（用户 2026-09-20 拍板：都要）

1. **备注 / 标签**：收藏条目可加自己的备注，可打标签（标签可多选，用于筛选）。
2. **导出**：把收藏导出成 Markdown（书名 / 章节 / 引用段落 / 提问 / 回复 / 备注），
   写到 `data/export/`，方便同步到笔记软件。后续可加 TXT。
3. **检索筛选**：除关键词外，支持按**时间范围**（全部 / 近 7 天 / 近 30 天）
   与**回复风格**筛选——所以写入条目时要记 `style`。

实现分两阶段：
- **阶段一（核心）**：数据字段扩展 + 收藏按钮 + 本书/全部收藏列表 + 关键词检索。
- **阶段二**：备注/标签、导出、时间与风格筛选。

## 二、OTA 更新 + 「关于」菜单（用户要求先记录，排在现有任务之后）

### 关于（先做，成本低）

菜单新增「关于」：插件说明、当前版本号、检查更新按钮。
版本号需要一个常量（建议放 `_meta.lua`，与 Release tag 对齐）。

### OTA 自动更新（后做，风险较高）

思路：查 GitHub Release 最新版本 → 下载 zip → 解压覆盖插件目录 → **保留 `data/`** → 提示手动重启。

**必须先解决的四个风险**（做之前先探）：
1. **域名白名单**：`ywbf/httpclient.lua` 目前只放行 `api.deepseek.com`，
   要加 `api.github.com` / `github.com`（且只能 https）。
2. **解压能力**：设备上的 busybox 未必有 `unzip`，需先验证；没有的话要么改用 Lua 解压，
   要么让用户手动拷。
3. **保留 data/**：覆盖升级最容易把 API Key / 收藏 / 历史一起清掉（我们已经在部署脚本上
   栽过一次，这里的风险更大，因为用户自己操作、没人兜底）。
4. **回滚**：升级失败要能退回上一个版本——建议升级前把整个插件目录打包备份。

### 排期

放在 M4 X-Ray 之后、M5 收尾里做。
